# 云开发部署

## 环境与依赖

使用自己的微信小程序 AppID 和云开发环境。将 AppID 填入根目录 `project.config.json`，将云环境 ID 填入 `miniprogram/config.js` 的 `env`。

本地安装 Node.js 后执行：

```sh
npm ci --prefix cloudfunctions/medicalApi
npm run check
npm test
```

## 数据库与云函数

创建以下 NoSQL 集合，权限全部设为“仅管理端可读写”：

`clinics`、`doctors`、`invitations`、`residents`、`records`、`rosters`、`services`、`exports`、`audioTasks`、`audits`。

业务集合建议建立 `clinicId` 与 `_id` 升序联合索引，用于分页。前端通过云函数访问数据，不直接查询数据库。

在微信开发者工具中部署 `cloudfunctions/medicalApi`，选择云端安装依赖。内存建议 512MB，超时 60 秒。包含 `font-data.js`、字体许可证和 `region-data/` 数据目录。函数入口为 `index.main`，通过 `wx.cloud.callFunction` 调用，不需要匿名 HTTP 入口。

## 服务环境变量

| 变量 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥 |
| `AI_MODEL` | 可选，覆盖默认模型；以服务账户实际可用模型为准 |
| `ASR_SECRET_ID` | 腾讯云 ASR SecretId |
| `ASR_SECRET_KEY` | 腾讯云 ASR SecretKey |
| `ASR_REGION` | 可选，默认 `ap-beijing` |
| `ASR_ENGINE` | 可选，默认 `16k_zh` |

其他 OpenAI 兼容服务可设置 `AI_API_URL`、`AI_API_KEY`、`AI_MODEL`；避免同时设置 DeepSeek 配置，以免提供方选择产生混淆。原生云开发模型可设置 `AI_PROVIDER=cloudbase` 并配置已开通的 `AI_MODEL`。

密钥仅配置在云函数环境变量，不写入小程序源码。未配置模型时提供基础模板整理；语音转写需要开通腾讯云录音文件识别。

## 文件与真机验证

云存储使用受限访问权限。导出文件经云函数权限检查后生成短期下载地址；在小程序公众平台配置实际下载域名。录音为 16kHz 单声道 MP3，最长 10 分钟，完成或失败后清理音频；中途退出遗留任务需由管理员定期清理。

微信登录后创建卫生室并选择地区，或使用负责人生成的邀请码加入。依次验证录音与转写、手动录入、AI 候选核对、草稿归档、居民档案、重点筛选、专家记录、PDF 与 Excel 的手机打开和保存。

首次部署不会自动创建案例或账号。正式发布通过微信公众平台提交审核、审核通过后发布；GitHub 开源不会自动发布小程序。

## 数据口径与限制

- 同一卫生室内居民编号唯一，档案与临床记录按 `clinicId` 隔离。
- 已归档病历不直接覆盖，草稿保存检查版本冲突。
- 筛选使用最新正式病历，多个条件按“或”匹配。
- 专家意见按“名单 + 居民”去重，关联居民历史。
- 转诊计数表示成功生成资料包次数，并不代表完成医疗转诊。
- 单集合汇总上限为 10000 条，超出需改用后台批次聚合。
- 五级行政区划数据的来源和时间范围见 `cloudfunctions/medicalApi/region-data/SOURCE.md`。
